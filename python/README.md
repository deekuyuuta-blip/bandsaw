# 帯鋸 き裂・破断予兆 監視ソフト

帯鋸にき裂が入ると、き裂部がガイドやホイールを通るたびに「カチッ」と鳴ります。
この音は **帯鋸1周（全長 ÷ 鋸速度）ごと** に繰り返します。
このソフトは打音の強弱を周波数分析し、**帯鋸1周の周波数（約5.8Hz）とその2倍に鋭い山が出ていないか** を常時監視します。
健全な帯鋸では、この山は出ません。

## 2026/10/27 CAM9 録画での検証（グラフ: `sample_result.png`）

| 時間帯 | 状態 | 30秒平均スコア | 判定 |
|---|---|---|---|
| 11:57:50〜12:02:52（約5分） | 午前・切削中 | 最大 5.9dB | 発報なし |
| 12:55:37〜12:58:30 | 昼休み明け（空運転？） | 最大 約5dB | 発報なし |
| 12:58:53〜 | 切削再開の直後から打音 | 上昇 | **12:58:59 警報** |
| 12:59〜13:08:50 | 打音が続く（7〜18dB、上下しながら上昇） | | 警報継続 |
| **13:08:50** | **破断** | | 警報から **約10分** |
| 15:27（交換後の帯鋸） | 切削中 | 最大 4.9dB | 発報なし |

- 午前中は、切削中でも打音は一度も出ていません。
- 昼休み明けに切削を再開した約20秒後から、帯鋸1周の周期（5.77Hz）の打音がはっきり出始めました。
- 平常時の大きな音（材の切削など）は「記録」だけにしてあります。破断音は、注意・警報中に出たときだけ発報します。

## 判定のしかた

1. 音声の 1.5〜4kHz（打音の帯域）を取り出し、音の強弱の波形（包絡線）を作る
2. 包絡線を対数にし、2Hz未満のゆっくりした変化（材の出入り・負荷変動）を取り除く
3. 直近8秒を周波数分析し、帯鋸1周の周波数（ホイール720〜830rpmの範囲で自動追従）とその2倍に、周りより何dB鋭い山があるかを計算 → **瞬時スコア(dB)**（0.5秒ごと）
4. 直近30秒の **平均スコア** と、**周波数の安定度**（き裂の打音は周波数がほぼ一定。雑音の山はふらつく）を計算
5. 判定

| 発報 | 条件 | 意味・推奨の対応 |
|---|---|---|
| 注意 | 30秒平均 ≥ 8dB かつ 安定度 ≥ 0.7 | き裂の疑い。早めに止めて点検・交換 |
| 警報 | 30秒平均 ≥ 11dB（安定度 ≥ 0.7）、または 瞬時 ≥ 14dB が1.5秒続く | き裂が進行中。できるだけ早く止めて交換。機械に近づかない |
| 解除 | 30秒平均 < 5dB が2分続く | （交換後など） |

実測値の幅:

| | 平常時 | き裂あり |
|---|---|---|
| 瞬時スコア 最大 | 10.4dB | 25dB |
| 30秒平均 最大 / 中央値 | 5.9dB / 約4dB | 17.6dB / 11.7dB |
| 周波数の安定度 | 0.5 以下 | ほぼ 1.0 |

き裂ありでも、13:02〜13:05 のように30秒平均が6〜8dBまで下がる時間があります。そのため、警報は一度出たら、平均が十分低い状態が2分続くまで解除しない設定にしています。

## 必要なもの

- Windows PC（Linux でも可）
- Python 3.9 以上 … https://www.python.org/ （インストール時に「Add python.exe to PATH」にチェック）
- ffmpeg … https://www.gyan.dev/ffmpeg/builds/ の「release essentials」を解凍し、`bin\ffmpeg.exe` の場所を config.ini の `ffmpeg =` に書く
- 音の入力: ①監視カメラ（CAM9など）の音声（RTSP）、または ②帯鋸の近くに置いたマイク

## セットアップ

```
pip install -r requirements.txt
```

`config.ini` を開いて設定:

- `[machine]` 帯鋸全長・ホイール径・回転数（入力済み: 8350 / 1200 / 720〜830）
- `[input] source` 音の入力元
  - カメラ/NVR の RTSP: `rtsp://ユーザー:パスワード@IPアドレス:554/…`（URLの形式はメーカーで違います）
  - Windows のマイク: `source = audio=マイク名` と `input_format = dshow`
    マイク名の調べ方: `ffmpeg -list_devices true -f dshow -i dummy`
- `[action]` 発報時の動作（下記）

## 使い方

```
python bandsaw_monitor.py run                    … 常時監視（start.bat のダブルクリックでも可）
python bandsaw_monitor.py analyze 録画.mp4        … 録画ファイルを検証。CSVとグラフを analyze_out に出力
python bandsaw_monitor.py learn 平常運転.mp4      … 平常時スコアを測り、しきい値の推奨値を表示
python bandsaw_monitor.py learn --minutes 10     … source から10分間測る
```

`analyze` で時刻を合わせたいとき: `--start 2026-10-27T13:08:21.5`

## 記録されるもの（logs フォルダ）

- `events.log` … 発報と大きな音の記録
- `score_日付.csv` … 0.5秒ごとのスコア
- `trend.csv` … 1分ごとの中央値・最大値。帯鋸ごとに数日分並べると、き裂が出始めた時期と進み方が分かります
- `日時_ALARM.wav` など … 発報時の直前30秒の音声

## 発報時の動作（config.ini の [action]）

- 画面表示と events.log への記録（常に）
- Windows のビープ音（`beep = yes`）
- 直前30秒の音声を WAV で保存（`save_audio_sec`）
- `command_warn` / `command_alarm` … 任意のコマンドを実行。パトライト、USBリレー、PLC入力などを動かすスクリプトを指定
- `webhook_url` … JSON を POST（Teams / Slack / 社内システムへの通知など）

## 導入時に必ずやること

1. **平常時のデータを増やす**: 今のしきい値は、平常時 約8分・き裂あり 約10分の録画（1日分・帯鋸1本）から決めています。帯鋸の交換直後から数日分の `trend.csv` を見て、平常時に注意が出ないことを確認してください。
2. **最初は表示と記録だけで運用する**: 誤報の頻度を確認してから、パトライトや停止信号につないでください。
3. **左側の帯鋸盤**: ツイン帯鋸の左右両方の音がマイクに入ります。左右で帯鋸の長さと回転数が同じだと、どちらの帯鋸か区別できません。発報したら両方を点検してください。
4. **周期的な別の音**: 送り装置やチェーンなどが偶然、毎秒5.4〜6.3回の周期で鳴ると誤検出の原因になります。

## 注意

- このソフトは **補助的な予兆検知** です。安全装置（非常停止・カバー・インターロック）の代わりにはなりません。
- 帯鋸を交換するときの目視点検（歯底のき裂・溶接部）は引き続き必要です。
- 自動停止につなぐ場合は、機械メーカーや安全担当と相談のうえで決めてください。
