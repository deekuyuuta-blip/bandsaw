# PLC 接続（三菱・シンプルCPU通信）

帯鋸打音モニター（Android アプリ）の状態を、PLC の **シンプルCPU通信** で PLC に取り込み、表示灯・ブザーに使います。
**機械を止める用途には使いません。**

```
 PLC（iQ-R など）  ── 読出し要求（SLMP 3Eフレーム） ──▶  スマホ（アプリが SLMP サーバーとして待ち受け）
                   ◀── D0〜D4 の5語 ─────────────────
```

- PLC の方から一定周期でスマホを読みに来ます。**PLC はポートを開けず、外部からの書込みも許可しません。**
- スマホは PLC からの読出しに答えるだけで、PLC のデバイスを書き換えることはできません。
- ラダーでの通信プログラムは不要です（パラメータ設定のみ）。

## データの割り当て（スマホ側 D0〜D39 ↔ PLC 側 D1000〜D1039 の例）

### アプリ → PLC（シンプルCPU通信「読出し」20点: スマホ D0〜D19 → PLC D1000〜D1019）

| スマホ | PLC（例） | 内容 |
|---|---|---|
| D0 | D1000 | 状態　0=停止・待機　1=準備中　2=平常　3=学習中　4=注意　5=警報 |
| D1 | D1001 | 生存カウンタ（0.5秒ごとに +1。待機中も増える。32767 の次は 0） |
| D2 | D1002 | 30秒平均スコア ×10（例: 11.7dB → 117） |
| D3 | D1003 | 瞬時スコア ×10 |
| D4 | D1004 | 未確認の警報　1=警報が鳴っている（「警報確認」で 0） |
| D5 | D1005 | 指令の受付カウンタ（指令を1つ受けるごとに +1） |
| D6 | D1006 | 最後の指令の結果　0=OK　2=監視を開始できない（マイク）　101〜110=設定値の範囲外（何番目の値か） |
| D7 | D1007 | 学習の進み具合 %（帯鋸交換後の基準づくり） |
| D8 | D1008 | 1=監視中　0=待機中 |
| D10〜D19 | D1010〜D1019 | 今の設定値（下の「設定値の並び」） |

### PLC → アプリ（シンプルCPU通信「書込み」20点: PLC D1020〜D1039 → スマホ D20〜D39）

| スマホ | PLC（例） | 内容 |
|---|---|---|
| D20 | D1020 | **指令ビット**　.0=開始　.1=停止　.2=帯鋸交換（基準の学習）　.3=警報確認　.4=設定を反映 |
| D21〜D30 | D1021〜D1030 | 新しい設定値（.4 で反映。並びは下表） |

- 指令は **ビットが 0→1 になったときに1回だけ** 実行します。1 のままにしても繰り返しません。
- アプリが起動したとき、最初に届いた時点ですでに 1 のビットは実行しません（一度 0 に戻してから 1 にしてください）。
- 開始と停止を同時に 1 にした場合はどちらも実行しません。
- 受け付けると D1005（受付カウンタ）が +1 になり、結果が D1006 に入ります。

### 設定値の並び（D10〜D19 / D21〜D30）

| 順 | 内容 | 単位 | 範囲 |
|---|---|---|---|
| 1 | 帯鋸の全長 | mm | 1000〜30000 |
| 2 | ホイール直径 | mm | 200〜3000 |
| 3 | ホイール回転数 最小 | rpm | 50〜3000 |
| 4 | ホイール回転数 最大 | rpm | 最小以上〜3000 |
| 5 | 注意: 30秒平均 | dB×10 | 10〜600 |
| 6 | 警報: 30秒平均 | dB×10 | 注意以上〜600 |
| 7 | 警報: 瞬時 | dB×10 | 10〜600 |
| 8 | 基準を覚える時間 | 分 | 1〜120 |
| 9 | 基準からの上昇で注意 | dB×10 | 0〜400 |
| 10 | 基準からの上昇で警報 | dB×10 | 0〜400 |

範囲外の値があると反映せず、D1006 に 100＋その順番（例: ホイール直径なら 102）が入ります。

### 待機について

PLC から「開始」できるように、アプリは監視を止めても **待機**（マイクは止め、PLC との通信だけ続ける）になります。
待機中も生存カウンタは増え、D1000=0、D1008=0 です。アプリの「終了」を押すと通信も止まります。
最初の一回はアプリを開いて「監視開始」か「待機する」を押してください（Android の制限で、マイクを使うサービスは画面から起動する必要があります）。

## 1. ネットワークとスマホの固定IP

1. PLC の LAN に Wi-Fi アクセスポイントをつなぐ（PLC 専用。WPA2/WPA3・強いパスワード。事務所 LAN やインターネットとはつながない）
2. スマホをその Wi-Fi に接続し、**固定IP** にする
   Android:「設定」→「Wi-Fi」→ 接続中の Wi-Fi の詳細 →「IP設定」を **静的** に
   | 項目 | 例（PLC が 192.168.3.39 の場合） |
   |---|---|
   | IPアドレス | 192.168.3.200（空いている番号） |
   | ゲートウェイ | 192.168.3.1 |
   | ネットワークプレフィックス長 | 24 |
3. アプリの「設定」→「PLC との連携」に「このスマホの IP」が表示されるので確認

## 2. アプリの設定

「設定」→「PLC との連携」

| 項目 | 設定 |
|---|---|
| PLC と連携する | チェック |
| 方式 | **PLC が読みに来る（シンプルCPU通信）** |
| 待ち受けるポート番号 | 例 **5000**（TCP・UDP の両方で待ち受け） |
| 先頭デバイス | 例 **0**（スマホの D0〜D39 を使う） |

監視を始めると、状態ランプの下に
「PLC からの読出し待ち（このスマホ 192.168.3.200/24 ポート 5000）」→ PLC が読みに来ると
「PLC が読出し中（192.168.3.39 UDP・0.4秒前）」（緑）と表示されます。

## 3. PLC のパラメータ（シンプルCPU通信）

GX Works3（iQ-R）: ナビゲーション →「パラメータ」→ CPU →「ユニットパラメータ」→ Ethernet ポートの **応用設定** にある **シンプルCPU通信設定** を「使用する」にして、詳細設定で **2行** 追加します。

| 項目 | No.1（状態を読む） | No.2（指令を書く） |
|---|---|---|
| 交信パターン | **読出し** | **書込み** |
| 交信設定 | 固定周期 **500ms** | 固定周期 **500ms** |
| 交信先の機種 | **SLMP対応機器**（QnA互換3Eフレーム） | 同左 |
| 交信先 IP アドレス | **スマホの固定IP**（例 192.168.3.200） | 同左 |
| 交信先ポート番号 | **5000**（アプリと同じ値） | 同左 |
| 交信先デバイス | **D0** から **20点** | **D20** から **20点** |
| 自局デバイス | **D1000** から 20点 | **D1020** から 20点 |

（指令を使わず状態を見るだけなら No.1 だけでも動きます）

パラメータを書き込み、PLC をリセット（または電源の入れ直し）します。

- Q シリーズは、シンプルCPU通信に対応している機種・シリアル番号が限られます（QnUDV の一部など）。お使いの CPU が対応しているか確認してください。
- 画面の名称や項目の並びはソフトのバージョンで違うことがあります。**MELSEC iQ-R Ethernet ユーザーズマニュアル（応用編）** の「シンプルCPU通信」で確認してください。
- シンプルCPU通信の交信状態は、診断（シンプルCPU通信診断）や特殊レジスタで確認できます。

## 4. ラダー例（自局 D1000〜D1004 に取り込む場合）

デバイス番号（M・T・Y・D1010）は例です。空いているものに置き換えてください。T は 100ms タイマとします。

```
(0)  ─┤<> D1001 D1010├──────────────────────( M1000 )   生存カウンタが変わった
(1)  ─┤ M1000 ├────────────────────[ MOV D1001 D1010 ]
(2)  ─┤/M1000├──────────────────────( T100  K50 )      5秒変化なし → T100 ON
(3)  ─┤ T100 ├──────────────────────( Y20 )           監視停止・通信断ランプ
(4)  ─┤= D1000 K4├──┤/T100├─────────( Y21 )           注意ランプ（黄）
(5)  ─┤= D1000 K5├──┤/T100├─────────( Y22 )           警報ランプ（赤）
(6)  ─┤= D1004 K1├──┤/T100├─────────( Y23 )           ブザー
```


### 指令のラダー例（押しボタン X10〜X13、確実に1回だけ届ける）

```
(10) ─┤↑X10├────────────────────────[ SET D1020.0 ]   開始
(11) ─┤↑X11├────────────────────────[ SET D1020.1 ]   停止
(12) ─┤↑X12├────────────────────────[ SET D1020.2 ]   帯鋸交換（基準の学習）
(13) ─┤↑X13├────────────────────────[ SET D1020.3 ]   警報確認
(14) ─┤<> D1005 D1011├──┬──[ MOV D1005 D1011 ]          受付カウンタが変わった
                         └──[ MOV K0  D1020   ]          → 指令ビットをすべて戻す
(15) ─┤<> D1020 K0├─────────────────( T101 K100 )    10秒たっても受付されない → T101 ON（通信を確認）
```

- 指令ビットは、アプリが受け付けて D1005 が変わるまで 1 のままにします。シンプルCPU通信の周期（500ms）より短いパルスだと届かないことがあるためです。
- 設定を変えるときは、D1021〜D1030 に値を MOV してから `SET D1020.4` します。結果は D1006（0=OK）で確認します。
- (15) は例です。受付待ちのタイムアウト表示が要らなければ省略できます。

- (0)〜(3): アプリの停止・Wi-Fi 切れ・スマホの電池切れなどで生存カウンタが5秒変わらないと T100 が ON になります（シンプルCPU通信が失敗すると D1000〜D1004 が更新されないため、同じく T100 で検知できます）。
- 警報ランプを点滅させるなら (5) に `SM412`（1秒クロック）を AND で追加します。
- ブザーはアプリの「警報を確認」または通知の「確認」で止まります。

## 5. 確認の手順

1. スマホを PLC の Wi-Fi に接続（固定IP）、アプリで設定を保存して「監視開始」
2. PLC を RUN
3. アプリの表示が「PLC が読出し中」（緑）になる
4. GX Works3 の「デバイス／バッファメモリ一括モニタ」で D1000〜D1004 を表示
   - D1001 が 0.5秒ごとに増える
   - D1000 が 1（準備中）→ 2（平常）になる

つながらないとき:
- アプリが「読出し待ち」のまま → PLC の交信先 IP・ポートとスマホの IP・ポートが合っているか、スマホと PLC が同じネットワーク（例 192.168.3.x）か
- アプリが「未対応の要求（コマンド ○○○○）」と表示 → その表示内容を連絡してください（アプリ側で対応します）

## 別の方式: アプリから PLC に書き込む

アプリの設定で「アプリから PLC に書き込む」を選ぶと、アプリが SLMP で PLC の D1000〜 に直接書き込みます。
この場合 PLC 側で SLMP 用のポートを開け、「RUN中書込み」を許可する必要があり、同じネットワーク内のどの機器からも PLC のデバイスを書き換えられる状態になります。シンプルCPU通信が使えない CPU の場合だけ使ってください。

PLC 側の設定（参考）:
- iQ-R（GX Works3）: ユニットパラメータ → Ethernet ポート → 基本設定「RUN中書き込み許可/禁止設定」= 一括で許可する（SLMP）、交信データコード = バイナリ、相手機器接続構成設定に「SLMP接続機器」（UDP、ポート 5000）
- Q（GX Works2）: PCパラメータ →「内蔵Ethernetポート設定」で「RUN中書込みを許可する」、オープン設定に UDP／MCプロトコル／ポート 5000

## 注意

- このアプリは補助的な予兆検知です。非常停止やカバーなどの安全装置の代わりにはなりません。
- 取り込んだ5語は表示灯・ブザーにだけ使ってください。
