# PLC 接続（三菱 Q / iQ-R・SLMP）

帯鋸打音モニター（Android アプリ）から、Wi-Fi 経由で PLC のワードデバイスに状態を書き込みます。
PLC 側はその値を見て表示灯・ブザーを出します。**機械を止める用途には使いません。**

## 書き込む内容（先頭デバイスから連続5語、例: D1000〜D1004）

| デバイス | 内容 |
|---|---|
| D1000 | 状態　0=停止　1=準備中　2=平常　3=学習中　4=注意　5=警報 |
| D1001 | 生存カウンタ（0.5秒ごとに +1、32767 の次は 0） |
| D1002 | 30秒平均スコア ×10（例: 11.7dB → 117） |
| D1003 | 瞬時スコア ×10 |
| D1004 | 未確認の警報　1=アプリで警報が鳴っている／0=それ以外（アプリの「警報を確認」で 0） |

- 0.5秒ごとに5語まとめて書きます（コマンド 1401、サブコマンド 0000、3Eフレーム・バイナリ）。
- アプリで監視を止めると、最後に D1000=0、D1004=0 を書きます。
- **ラダーで使っていないデバイスを選んでください。** 先頭は D／W／R／ZR から選べます。

## 1. ネットワーク

- PLC の LAN に Wi-Fi アクセスポイントをつなぎ、スマホをその Wi-Fi に接続します。
- スマホと PLC は同じネットワーク（例: 192.168.3.x）にします。
- アプリは PLC への通信を必ず Wi-Fi で送ります（Wi-Fi がインターネットにつながっていなくても可）。

## 2. PLC のパラメータ

### iQ-R（GX Works3）

1. ナビゲーション →「パラメータ」→ CPU →「ユニットパラメータ」→「Ethernetポート」
2. 基本設定
   - 自局設定: IP アドレスを確認（アプリに入れる値）
   - 交信データコード: **バイナリ**
   - 「相手機器接続構成設定」→「詳細設定」で **SLMP接続機器** を追加
     - プロトコル: **TCP**（または UDP）
     - 自局ポート番号: 例 **5000**（アプリに入れる値）
3. 応用設定 →「RUN中書込み設定」を **許可する（全て）**
4. パラメータを書き込み、CPU をリセット

### Q シリーズ 内蔵 Ethernet（QnUDE(H) など / GX Works2）

1. 「PCパラメータ」→「内蔵Ethernetポート設定」
2. IP アドレスを確認、交信データコード: **バイナリコード交信**
3. **「RUN中書込みを許可する（FTPとMCプロトコル）」にチェック**
4. 「オープン設定」で 1行追加
   - プロトコル: **TCP**（または UDP）、オープン方式: **MCプロトコル**
   - 自局ポート番号: 例 5000（**GX Works2 の入力が16進の場合は 1388**）
5. パラメータを書き込み、CPU をリセット

> 画面の名称はソフトのバージョンで多少違います。お使いの CPU のマニュアル（SLMP／MCプロトコル、内蔵 Ethernet）で確認してください。

## 3. アプリの設定

「設定」→「PLC への送信」

| 項目 | 例 |
|---|---|
| PLC に状態を送る | チェック |
| PLC の IP アドレス | 192.168.3.39 |
| ポート番号 | 5000 |
| UDP で送る | PLC 側に合わせる（TCP ならチェックなし） |
| 先頭デバイス | D |
| 先頭番号 | 1000 |

監視中は状態ランプの下に「PLC 送信中: …」（緑）と出ます。送れないと黄色で理由が出ます。

## 4. ラダー例（D1000〜D1004 を使う場合）

デバイス番号（M・T・Y・D1010）は例です。空いているものに置き換えてください。T は 100ms タイマとします。

```
(0)  ─┤<> D1001 D1010├──────────────────────( M1000 )   生存カウンタが変わった
(1)  ─┤ M1000 ├────────────────────[ MOV D1001 D1010 ]
(2)  ─┤/M1000├──────────────────────( T100  K50 )      5秒変化なし → T100 ON
(3)  ─┤ T100 ├──────────────────────( Y20 )           監視停止・通信断ランプ
(4)  ─┤= D1000 K4├──┤/T100├─────────( Y21 )           注意ランプ（黄）
(5)  ─┤= D1000 K5├──┤/T100├─────────( Y22 )           警報ランプ（赤）
(6)  ─┤= D1004 K1├──┤/T100├─────────( Y23 )           ブザー
```

- (0)〜(3): アプリが止まった・Wi-Fi が切れた・スマホの電池切れなどで生存カウンタが 5 秒変わらないと T100 が ON になります。監視されていないことを表示できます。
- 警報ランプを点滅させるなら (5) に `SM412`（1秒クロック）を AND で追加します。
- ブザーはアプリの「警報を確認」または通知の「確認」で止まります（D1004=0）。

## 5. 確認の手順

1. PLC を RUN、スマホを PLC の Wi-Fi に接続
2. アプリで設定を保存し「監視開始」
3. GX Works の「デバイス／バッファメモリ一括モニタ」で D1000〜D1004 を表示
   - D1001 が 0.5秒ごとに増える
   - D1000 が 1（準備中）→ 2（平常）になる
4. 「警報をテスト」は PLC には送られません（音・振動・通知の確認用）

## 注意

- 書き込みは指定した5語だけですが、**RUN 中に外部から PLC のデバイスを書き換える設定**になります。使っていないデバイスを選び、ラダーではこの5語を表示灯・ブザー以外に使わないでください。
- このアプリは補助的な予兆検知です。非常停止やカバーなどの安全装置の代わりにはなりません。
